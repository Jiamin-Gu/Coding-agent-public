# 使用教程

## 配置

点网页右上角的 **⚙**（或者点模型名）打开「模型设置」：

1. **服务商**：DeepSeek 官方 / 自定义（其他任何 OpenAI 兼容服务）。选了预设的服务商，接口地址会自动填好
2. **模型**：可以从常用模型里选，也可以直接输入
3. **API Key**：已经设置过的话留空即可，不会被覆盖

保存后立即生效，当前对话的历史保留。设置写在 `.env` 里（面板上会显示具体路径），密钥只存在你的电脑上，不会发给浏览器。也可以直接编辑 `.env`：

```
CODER_PROVIDER=deepseek
CODER_API_KEY=你的密钥
CODER_BASE_URL=https://api.deepseek.com
CODER_MODEL=模型名
```

- **不同服务商的兼容**：项目只按标准的 OpenAI 兼容接口调用（接口地址 + 密钥 + 模型名），不加任何额外请求头。没有任何服务商专属的代码；其他服务商、自己搭的中转或代理，都选「自定义」填接口地址即可
- 没写 `CODER_PROVIDER` 的旧配置会按接口地址自动识别
- 带思考能力的模型（返回 `reasoning_content`）也支持，界面上会显示它的思考过程
- 命令行版（`python -m coder`）和评测也读取同一个 `.env`
- 可选：`CODER_CONTEXT_LIMIT`（默认 200000）——上下文超过这么多 token 时才自动压缩，设为 0 表示不压缩。现在的模型上下文窗口普遍几十万起步，压缩只是兜底
- `.env` 已经写在 `.gitignore` 里，不会被提交到 Git

## 用 pip 安装（可选）

在项目根目录执行，之后在任何目录都能用命令启动：

```bash
pip install -e .
coder-web            # 等同于 python -m coder.web
coder 工作区路径       # 命令行版
```

pip 安装后，配置也可以放在 `~/.coder/.env`（Windows：`C:\Users\<用户名>\.coder\.env`）。

## 手动启动（不用脚本）

```bash
pip install -r requirements.txt

# 创建配置文件，然后按上面的"配置说明"编辑它
copy .env.example .env      # Windows
cp .env.example .env        # macOS / Linux

python -m coder.web
```

`python -m coder...` 命令要在**项目根目录**（clone 下来的 `Coding-agent-public` 文件夹）里运行，否则会报 `No module named coder`。

## 选择工作区

服务启动后，终端显示 `coder vX.Y.Z 已启动：http://127.0.0.1:8765`，浏览器会自动打开这个地址。

- **第一次启动**：页面会让你选择**工作区**，也就是 agent 可以读写的文件夹。点 **浏览…** 用系统对话框选择，或者粘贴路径后点 **打开**。agent 无法访问工作区以外的文件。建议先新建一个空文件夹练手
- **之后再启动**：自动打开上次的对话，可以接着聊
- 也可以启动时直接指定工作区，例如 `python -m coder.web ~/projects/my-app`（Windows：`python -m coder.web D:\projects\my-app`，或者把文件夹拖到 `start.bat` 上）
- 同一个端口同时只能运行一个 coder
- **只是想问个问题、要一道题的解法**：不用选工作区，直接在输入框里提问（已经打开了项目的话，点顶栏的工作区，选"不用工作区，直接提问"）。agent 会用一个临时工作区（`~/.coder/scratch/` 下，每个对话一个）自己跑代码验证，解法直接写在回复里，不会碰你的项目。对话列表里标着"临时对话"，删除时临时工作区一起删掉

## 给 agent 布置任务

在底部输入框描述任务，按 Enter 发送，比如"写一个计算器模块，配上 pytest 测试并跑通"。你会看到：

1. agent 的**思考过程**和回复逐字出现（思考过程可以折叠）
2. 每次调用工具都会出现一张**卡片**，比如读文件、搜索、写文件、运行命令
3. 写文件或执行命令前，卡片里会显示**红绿 diff**，等你点按钮确认
4. 右侧文件树实时刷新，改过的文件标 **M**，点开能看内容
5. 最后 agent 会总结改了什么

## 发送图片：比如用 LeetCode 题目测试 agent

如果模型支持视觉，可以把截图和文字一起发给 agent。三种添加方式：

- 截图后在页面里直接按 **`Ctrl+V`** 粘贴（截图到剪贴板：Windows 按 `Win+Shift+S`，macOS 按 `Cmd+Ctrl+Shift+4`）
- 把图片文件**拖进**对话区域
- 点输入框左边的**图片按钮**选择文件

一次最多 4 张。发送前可以点缩略图预览、点 ✕ 移除；超过 2000 像素的大图会自动缩小。

**用 LeetCode 测试 agent 的流程：**

1. 在 LeetCode 上截取题目描述（包括示例和代码模板），或者直接复制题目文字
2. 在 coder 里新建对话，粘贴截图，点空状态页的示例"**粘贴 LeetCode 题目截图，写出解法并用示例测试**"自动填好要求，发送
3. agent 会读题、写解法、把示例写成测试并运行，最后给出完整代码
4. 鼠标移到代码块上，点右上角的"**复制**"，粘贴回 LeetCode 提交

> 图片会一直留在对话上下文里，之后每一轮都会重新发送。建议**每道题开一个新对话**，节省 token。只在练习题上用，不要在周赛等比赛中使用，那违反 LeetCode 的规则。

## 没有 API key？先用演示模式

```bash
python -m coder.web --demo
```

用一个按固定剧本执行的假模型走完整个流程（看目录 → 建文件 → 运行 → 修改 → 再运行），不调用 API，在临时目录里操作，对话记录也不会混进真实历史。页面顶部会显示黄色的"演示模式"横幅。

**看完记得在终端按 `Ctrl+C` 关闭演示服务**，再用 `python -m coder.web` 启动真实模式。

## 界面说明

| 位置 | 作用 |
|---|---|
| 左侧栏 | **＋ 新对话**：在当前工作区开一个新对话（当前对话还没发消息时，它本身就是新对话）。下面是**历史对话**，点击切换，悬停出现 ✕ 可删除（只删记录，不删文件） |
| 顶栏 📁 按钮 | 显示当前工作区，点击可以换到别的文件夹（会开一个新对话） |
| 顶栏绿点 | 已连接服务；变红说明后台服务停了 |
| 模型名 | 当前使用的模型，悬停显示接口地址 |
| 自动模式开关 | 打开后，写文件和执行命令不再逐个确认（危险命令仍会被拦截） |
| token 数 | 本对话累计用量，实时更新；悬停看输入、输出和缓存命中的拆分 |
| 顶部横幅 | 黄色：当前是演示模式。红色：页面连到了旧版本的服务，需要关掉旧服务重新启动 |
| 思考过程 | 模型的推理内容，生成时自动展开，结束后收起，点击可再展开 |
| 工具卡片 | 点击展开参数和结果。图标：转圈=运行中，✓=成功，✕=失败或被拒绝，?=等你确认 |
| 确认卡片 | **允许**：执行这一次。**本对话总是允许**：这类工具之后不再询问。**以后总是允许「…」开头的命令**：只对命令出现，比如 `python -m pytest`，保存在项目的 `.coder/permissions.json`，下次打开仍然有效（在 ⚙ 设置里可以删除）。**拒绝…**：可以写一句理由告诉 agent 该怎么改 |
| 顶栏 ↶ 按钮 | 撤销上一轮 agent 对文件的修改：改过的恢复原样，新建的删除。之后又被你手动改过的文件会先提示，确认后才覆盖。命令产生的效果（安装依赖、命令生成的文件）无法撤销 |
| 停止按钮 | 任务运行时发送按钮变成停止，模型生成中途也能立即停下 |
| 图片按钮 | 输入框左边，添加图片；也可以直接 `Ctrl+V` 粘贴截图或拖入文件。点消息里的图片可以看大图 |
| 复制按钮 | 鼠标移到 agent 回复里的代码块上，右上角出现"复制" |
| 右侧文件树 | agent 改过的文件标 **M**；点文件名查看内容，agent 改动后自动刷新 |

窄屏时，左侧栏和文件树会收起，分别用左上角 ☰ 和右上角"文件"按钮打开。

**数据保存在哪**：对话和图片保存在用户主目录下的 `.coder` 文件夹（macOS/Linux：`~/.coder`；Windows：`C:\Users\<用户名>\.coder`），可以用环境变量 `CODER_HOME` 改位置。刷新页面、关闭浏览器、重启服务都不会丢失。

## 命令参数

```bash
python -m coder.web [工作区路径] [--demo] [--auto] [--port 8765] [--model 模型名] [--no-browser]
```

| 参数 | 说明 |
|---|---|
| `工作区路径` | 直接在这个目录开一个新对话。不填则打开上次的对话，或在页面上选择 |
| `--demo` | 用脚本化的假模型，不需要 API key |
| `--auto` | 一启动就开着自动模式 |
| `--port` | 换一个端口，比如 `--port 9000` |
| `--model` | 临时换模型，覆盖 `.env` 里的 `CODER_MODEL` |
| `--no-browser` | 不自动打开浏览器 |

不想用浏览器的话，也有命令行版本：

```bash
python -m coder 工作区路径                          # 交互模式，输入 /help 查看命令
python -m coder 工作区路径 --auto -p "修复失败的测试"   # 一次性执行任务后退出，适合脚本调用
```

命令行里输入 `/compact` 可以手动压缩上下文，`/usage` 查看 token 用量和当前上下文大小，`/undo` 撤销上一轮的文件修改，`/rules` 查看和删除命令白名单，`/ps` 查看和停止 agent 启动的后台进程，`/mcp` 查看 MCP 服务器。

## 沙箱模式（Docker）

默认情况下 agent 直接改你的项目，命令也直接在你的电脑上执行（每条都会先问你，除非开了自动模式）。开启沙箱模式后：

- **agent 在项目的副本上工作**：副本放在 `~/.coder/sandbox-copies/` 里，读写文件、执行命令、撤销都只作用于副本，真实项目在你确认之前不会被改动
- **每轮结束列出改动**（新增 / 修改 / 删除的文件）：网页上点「应用到项目」或「放弃」；命令行里选 `[a]` 应用、`[d]` 放弃、`[k]` 先保留。不处理也可以接着发下一条，改动会累积
- 应用时，如果某个文件在这期间你自己也在项目里改过，不会覆盖它，而是列为冲突，你可以对照副本手动合并
- 没有待应用的改动时，每轮开始前会把你在项目里做的修改同步进副本
- `node_modules`、`.venv` 这类依赖和缓存目录不复制（需要时在容器里重新装，也不会同步回去）；`.git` 会复制一份，agent 能看 `git status`，但 `.git` 里的变化不会同步回项目，提交由你自己做
- 副本里还有没应用的改动时不能关闭沙箱；删除对话会连副本一起删。命令行退出时会删掉副本（有没处理的改动会先问你）；一次性模式（`-p`）没人可问，任务结束后直接应用
- 命令在 Docker 容器里执行，容器挂载的是副本（在 `/workspace`），看不到你的其他文件
- **默认断网**。命令确实需要联网时（比如 `pip install`），agent 会单独申请，**即使开着自动模式也要你亲自确认**，执行完立即断开
- 非 root 用户、根文件系统只读、限制内存 4G / CPU 4 核 / 进程数 512
- 镜像里装好了 Python 3.12、Node.js 22、git、gcc/make、curl、ripgrep；pip / npm 装的包和缓存放在一个持久卷里，下次不用重新下载

使用步骤：

1. 安装 [Docker Desktop](https://www.docker.com/products/docker-desktop/) 并打开它。C 盘空间紧张的话，在 Docker Desktop 的 Settings → Resources → Advanced 里把 Disk image location 改到别的盘
2. 构建镜像（只需一次，约下载 370MB，构建后约 600MB）：`python -m coder.sandbox build`（国内网络慢可以加 `--apt-mirror mirrors.tuna.tsinghua.edu.cn`）
3. 开启：网页 ⚙ 设置里勾选「沙箱模式」（保存到 `.env`），或命令行加 `--sandbox`，或在 `.env` 里写 `CODER_SANDBOX=1`。开启后顶栏显示「沙箱」

```bash
python -m coder.sandbox status   # 检查 Docker 和镜像是否就绪
python -m coder.sandbox clean    # 删除残留的沙箱容器（正常情况下会自动清理）
```

**预览沙箱里的服务**：agent 在沙箱里用后台进程启动开发服务器（`npm run dev`、`python -m http.server` 等）后，容器里新出现的监听端口会自动转发到本机的 `127.0.0.1`（尽量用同一个端口号），工具结果里给出预览地址，网页顶栏出现「预览 :端口 ↗」链接。容器本身仍然断网：转发走的是 `docker exec`，和 `kubectl port-forward` 一样。

注意：沙箱里是 Linux，Windows 专用的命令在沙箱模式下用不了；读写文件的工具在本机执行，但只能访问副本。

## MCP 工具：联网查资料、搜索、操作浏览器

coder 内置了 MCP 客户端，可以接入任何 MCP 服务器提供的工具；服务器本身需要你自己准备。配置写在项目的 `.coder/mcp.json` 或用户的 `~/.coder/mcp.json`（同名的项目优先），用通用的 mcpServers 格式（Cursor、Claude 等工具都用这种）。

**例子：让 agent 能读网页、操作浏览器**（两个公开的现成服务器）

1. 读网页：官方的 fetch 服务器，`pip install mcp-server-fetch`
2. 浏览器：微软的 [Playwright MCP](https://github.com/microsoft/playwright-mcp)，需要先装 [Node.js](https://nodejs.org/)，第一次运行时 `npx` 会自动下载
3. 新建 `~/.coder/mcp.json`（Windows 是 `C:\Users\你的用户名\.coder\mcp.json`）：

```json
{"mcpServers": {
  "fetch":   {"command": "python", "args": ["-m", "mcp_server_fetch"]},
  "browser": {"command": "npx", "args": ["@playwright/mcp@latest", "--headless"]}
}}
```

新建一个对话，agent 就多了 `mcp__fetch__fetch`、`mcp__browser__browser_navigate` 等工具。其他写法：

- 远程的 MCP 服务器（Streamable HTTP）：`{"type": "http", "url": "https://服务器地址/mcp"}`
- 需要密钥的服务器：在 `env` 里写 `{"TOKEN": "${MY_TOKEN}"}`，`${...}` 会换成同名的环境变量，密钥不用写进配置文件
- 搜索类的服务器一般要搜索服务的 API Key，按各自的说明配置

- 每个工具变成 agent 的一个工具（名字是 `mcp__服务器名__工具名`），调用前和写文件一样要你确认，可以选"本对话总是允许"
- 工具返回的图片（比如截图）保存在工作区的 `.coder/mcp-files/`，结果里写上路径
- 命令行输入 `/mcp` 查看已连接的服务器和工具；网页在 ⚙ 设置里查看。配置改了以后新建对话生效
- 服务器在本机运行，不在沙箱里：它们是你自己配置、信任的程序

几个 agent 都要联网时，可以在本机跑一个 MCP 中枢，统一管理读网页、搜索、浏览器这些服务器，对外只提供一个地址，各个 agent 都连它，不用各自配置（配置里写成远程服务器的形式就行）。工具多的服务器按需开启：比如 Playwright 浏览器有 25 个工具，每次调用模型都要带上它们的定义，只在做前端的项目里加。

## 团队模式

网页右上角打开「团队模式」开关（命令行加 `--team`）。主 agent 遇到大任务时先定好接口契约，再把模块拆给子 agent 并行完成；小任务它会自己写。子 agent 的工具调用卡片上会标出它负责的任务名。

**派发不阻塞**：主 agent 派出子 agent 后马上返回，子 agent 在后台并行运行，每个做完汇报就送到主 agent；依赖它的任务可以立刻派出，不用等同一批里最慢的那个。主 agent 在等待时也能回答子 agent 在黑板上的提问。子 agent 必须用 `complete_task` 交付，系统检查负责的文件在不在、Python 能不能编译、改了代码之后有没有验证过，不通过退回给它自己改。返工改了文件时，依赖它、已经完成的任务会收到通知。

子 agent 按现实中的工程职责分工：

| 岗位 | 什么时候出场 | 做什么 |
|---|---|---|
| 测试（tester） | 团队模式下**总是出场**，默认 1 个 | 根据需求写验收测试；实现完成后运行全部测试，汇报失败和可能的原因 |
| 安全审查（security） | 团队模式下**总是出场**，默认 1 个 | 只读，检查命令注入、SQL 注入、路径穿越、不安全的反序列化、写死的密钥等，按严重程度汇报，由文件的负责人修复 |
| 前端 / 后端 / 数据库 / 命令行与工具库 / 文档 | 主 agent 按项目类型选 | 各自有专门的职责说明；大项目里同一个岗位可以开多个，分别负责不同模块 |

规模大时自动增加质量岗位：大约每 8 个实现任务配 1 个测试、每 8 个配 1 个安全审查，各最多 3 个。测试和安全审查的步数上限比实现任务小（30、20 步）；全部实现完成后由主 agent 自己运行一次验收测试，失败的交给负责的任务。即使主 agent 自己写了代码，结束前也会被要求派出测试和安全审查各检查一遍。

```bash
python -m coder 工作区路径 --team          # 由主 agent 判断要不要拆分（推荐）
python -m coder 工作区路径 --team always   # 必须拆分（主要用于对比实验）
```

什么时候值得开：项目明显由几个相互独立的模块组成、单个 agent 一次装不下全部需要反复查看的内容时。上下文够用时拆分只会增加成本（见"评测"一节的对比）。

## 常见问题

- **`No module named coder`**：没有在项目根目录运行。先 `cd` 到 clone 下来的 `Coding-agent-public` 文件夹
- **`No module named fastapi` 之类**：依赖没装全，重新执行 `pip install -r requirements.txt`（用了虚拟环境的话，先激活它）
- **提示"未找到 CODER_API_KEY"**：`.env` 文件不存在或密钥没填；也可以先加 `--demo` 看效果
- **启动时提示"端口 8765 已被占用"**：之前启动的 coder（包括演示模式）还在运行。找到那个终端窗口按 `Ctrl+C` 关闭，或者用 `--port 8766` 换个端口
- **页面顶部是红色横幅 / 右上角显示 demo / 按钮没反应**：浏览器连到了之前没关的旧服务。关闭所有正在运行的 coder，再重新启动
- **API 调用失败**：检查 `.env` 里的密钥、接口地址和模型名是否正确，以及账户余额
- **发图片后报错 400**：当前模型可能不支持图片输入，换一个支持视觉的模型，然后新建对话
- **点"浏览…"没有弹出窗口**：对话框可能藏在其他窗口后面，看一下任务栏；也可以直接粘贴路径。在没有图形界面的环境（比如远程服务器）里只能手动输入路径
- **界面显示的还是旧版本**：按 `Ctrl+F5`（macOS：`Cmd+Shift+R`）强制刷新
- **顶栏的点是红色**：后台服务已经停了，回终端看看是否报错
- **打开页面显示"需要访问令牌"**：为了防止其他网站操作你的 agent，第一次要用启动时打开的链接（带 `?token=…`）。重新运行 `start.bat` 会自动用正确的链接打开；之后这个浏览器直接打开 `http://127.0.0.1:8765` 也可以
- **沙箱模式开不了**：运行 `python -m coder.sandbox status` 看原因，通常是 Docker Desktop 没打开或还没构建镜像
