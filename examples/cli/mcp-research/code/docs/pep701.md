## 二、它解决了什么问题

f-string 最初由 **PEP 498** 引入。PEP 498 只给出了 f-string 的语法描述，**没有提供正式文法**，并且为了让 CPython 在不改动既有词法分析器（lexer）的前提下能解析它，附加了一系列限制。这些限制对语言使用者而言没有实际意义，主要包括：

1. **不能在表达式部分复用包围 f-string 的引号**：

   ```pycon
   >>> f'Magic wand: { bag['wand'] }'
   SyntaxError: invalid syntax
   ```

2. **绕开限制的写法会引入转义序列，而 f-string 里又禁止转义**：

   ```pycon
   >>> f'Magic wand { bag[\'wand\'] } string'
   SyntaxError: f-string expression portion cannot include a backslash
   ```

3. **即便多行 f-string 也不允许注释**：

   ```pycon
   >>> f'''A complex trick: {
   ...     bag['bag']  # recursive bags!
   ... }'''
   SyntaxError: f-string expression part cannot include '#'
   ```

4. **无法自由嵌套**（相比 Ruby / JavaScript / Swift / C# 等支持字符串插值的语言，缺少任意嵌套表达式的能力）。

除了这些表层限制，实现层面还有两个更根本的问题：

- CPython 把 f-string 先当作一根 `STRING` token，再做后处理。这部分解析代码是**手写**的，历史上导致大量不一致和 bug，且需要手动管理原始 lexer 缓冲区的内存，维护成本高、容易出错。
- f-string 由独立于 PEG 解析器的机制解析，因此**无法享受 PEG 解析器（PEP 617）带来的改进错误提示**。这在诸如 `f"{y:=3}"`（并非赋值表达式）这类容易混淆的场景下尤其可惜。
- f-string 不属于官方文法，导致 PyPy 等基于 CPython PEG 文法的其他实现**无法判断自己是否实现正确**。

---

## 三、主要改动

PEP 701 在 PEG 解析器（PEP 617）之上，为 f-string 提供了**正式的 PEG 文法**，把它直接集成进解析器，并明确区分「字符串部分」与「表达式（替换字段 `{...}`）部分」。核心改动如下：

### 1. 提供正式文法 / 新增专用 token

f-string 被拆成三种新 token：

- **FSTRING_START**：包含前缀（`f` / `F` / `fr`）与开引号；
- **FSTRING_MIDDLE**：字符串中非表达式部分、也非花括号的文本；
- **FSTRING_END**：闭引号。

这些 token 属于 CPython 的公开 API（如 `tokenize` 模块）需要支持的一部分。

### 2. 解除限制，表达式里可以写「任何合法的 Python 表达式」

- 允许**复用引号**；
- 允许**反斜杠**；
- 允许**换行与注释**；
- 允许**任意嵌套**（规范只要求实现至少支持 **5 层** f-string 嵌套、**2 层**格式说明符嵌套）。

唯一保留的「反直觉」限制是：由于 `:` 被用来分隔格式说明符，**顶层含 `:` 的表达式（如 `lambda`）仍需加括号**。

### 3. 不改变 AST，向后兼容

新文法会保留与旧实现相同的抽象语法树（AST），**对既有代码没有语法或语义上的破坏性变更**。Python 3.8 引入的 `=` 调试表达式（如 `f"{1+1=}"`）不受影响。

## 四、代码示例（取自 PEP 原文）

**示例 1：表达式里可以复用外层引号**

```pycon
>>> f" something { my_dict["key"] } something else "
```

**示例 2：表达式里可以写反斜杠（此前会报错）**

```pycon
>>> a = ["hello", "world"]
>>> f"{'\n'.join(a)}"
'hello\nworld'
```

**示例 3：多行表达式 + 注释**

```pycon
>>> x = 1
>>> f"___{
...     x
... }___"
'___1___'
```

**示例 4：任意嵌套 f-string**

在此之前，因为不能复用引号，最多只能嵌套到：

```pycon
>>> f"""{f'''{f'{f"{1+1}"}'}'''}"""
'2'
```

PEP 701 之后可以自由嵌套：

```pycon
>>> f"{f"{f"{f"{f"{f"{1+1}"}"}"}"}"}"
'2'
```
